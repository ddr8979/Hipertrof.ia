===============================================================================
1. QUÉ ES
===============================================================================
PWA "web-first" (instalable en iOS/Android, wrapper Capacitor) para ATLETAS y
PERSONAL TRAINERS. Bloques:
  - Entrenamiento: rutinas, ejecutar sesión (diario de cargas), ejercicios,
    historial, progreso, calculadora, glosario.
  - Trainer: vinculación trainer↔alumno, asignar rutinas/recetas, cursos,
    suscripciones, mensajería.
  - Social/vida: dashboard, feed, perfiles, recetas/nutrición, chat, música.

Repositorio: /home/ddr/Documentos/HIPERTROFIA
  - web/                     → app Next.js + Capacitor
  - web/supabase/migrations/ → SQL = fuente de verdad del modelo
  - docs/architecture/       → documentación
  - web-legacy/, dev.db      → legado, IGNORAR


===============================================================================
2. STACK REAL
===============================================================================
- Framework: Next.js 16.3.1 (App Router, RSC), React 19.0.2, TypeScript.
- UI: Tailwind CSS v4, lucide-react. Iconos SVG inline para marcas.
- Backend/DB: Supabase = Postgres + RLS + Auth + Realtime + Storage + RPC.
- Estado cliente: Zustand 5 (con persist) + TanStack Query 5.
- Integraciones: Spotify OAuth PKCE, YouTube/oEmbed, Web Push (web-push).
- Mobile: Capacitor 8.5 (Android; iOS PWA).
- Deploy: Vercel.
- Cliente Supabase: @supabase/ssr (browser, server, middleware) + service_role
  en route handlers.

Regla de oro: ~90% de los datos viaja DIRECTO del navegador a Supabase con RLS
como control de acceso. Next.js NO es una API REST de dominio: solo hace SSR de
layouts/auth y expone /api/* para integraciones externas.

10. FLUJOS CLAVE (para diagramas de secuencia)
===============================================================================
10.1 AUTH
  Proveedor: Google OAuth | Magic link | Email+password.
  - OAuth/magic → /auth/callback → exchangeCodeForSession.
  - Si profiles.onboarded=false → /onboarding; si true → destino `next`.
  - middleware.ts: refresca token, rate-limit 60 req/min/IP, seguridad,
    redirige a /login?next=<ruta+query>.
  - (app)/layout.tsx: exige sesión y onboarded=true.
  - ProfileSync (providers.tsx): carga profiles con select('*') + retry/backoff
    y fallback desde el JWT. (Se eliminó el loader duplicado ProfileProvider.)

10.2 CREAR/EDITAR RUTINA
  /rutinas → editor con borrador en useState local → INSERT routines →
  INSERT routine_exercises (o UPDATE + DELETE sobrantes). SIN TRANSACCIÓN:
  si falla un paso quedan rutinas huérfanas/vacías.

10.3 EJECUTAR ENTRENAMIENTO (/entrenar?routine=ID)
  1. SELECT routines + routine_exercises + exercises (RLS; si no puede leer la
     rutina asignada → sesión vacía).
  2. Zustand startWorkout + addExercise por ejercicio; carga pesos del último
     workout.
  3. Usuario marca series (instantáneo, offline, persistido en localStorage).
  4. "Finalizar": UPSERT workouts → trigger handle_workout_insert (racha+feed)
     → INSERT workout_exercises (uno a uno) → INSERT workout_sets (batch) →
     RPC unlock_achievements → discardWorkout.
  Punto débil: hijos DESPUÉS del trigger y SIN transacción → reintentos
  duplican series.

10.4 TRAINER ↔ ALUMNO (nuevo, invitación + aceptación)
  Trainer: /entrenadores → "Invitar" → RPC create_trainer_invite → link
    {APP_URL}/entrenadores?invite=CODE + QR + Web Share.
  Alumno: abre link (o tipea el código) → RPC get_trainer_invite (preview) →
    RPC accept_trainer_invite → INSERT/UPDATE trainer_clients status=active.
  Alta directa: trainer busca alumno → upsert trainer_clients status=pending →
    el alumno acepta (update active) o rechaza (update terminated).
  Trainer ve "Esperando aceptación" + cancelar.
  NOTA histórica: antes el trainer insertaba status=active sin consentimiento,
  y "Registrarme como trainer" fallaba por el trigger de escalada; ahora se usa
  /api/trainer/role con service_role.

10.5 CHAT / DM
  /mensajes lista vía RPC get_conversations (refetch 15s) + Realtime para
  nuevos mensajes. /mensajes/[id] envía con RPC send_message o INSERT
  direct_messages (imagen → bucket dm-images), view-once, reacciones, borrado.
  Push vía /api/push/send (protegido por x-hook-secret; hoy sin caller claro).

10.6 SOCIAL / FEED
  /explorar lista feed_posts (global o de seguidos), like (post_likes),
  comentarios (post_comments + Realtime), compartir rutina/receta (scope),
  seguir usuarios (followers). Perfil público/privado según flags.

10.7 NUTRICIÓN
  /nutricion: catálogo recipes, recetas propias (user_id, steps, photos),
  meal_logs, daily_entries (cierre de día), macronutrientes; recetas asignadas
  por trainer (assigned_recipes, en drift).

10.8 SPOTIFY / MÚSICA
  /api/spotify/auth (PKCE, state=user.id, cookie verifier) →
  /api/spotify/callback → upsert spotify_tokens → /api/spotify/{data,search,
  share}. lib/spotify-token.ts refresca el token. UI: components/spotify-now.tsx.

       el alumno no abría la rutina asignada (sesión vacía).
       → migración 20260916000000 (pendiente de aplicar a la DB).

       → RESUELTO en código (select('*') + loader único).
  P0-3 Trigger prevent_privilege_escalation revertía role → "Registrarme como
       trainer" no hacía nada. → RESUELTO con /api/trainer/role (service_role).
  P0-4 assigned_recipes no existe en migraciones → recetas asignadas muertas.
  P0-5 tablas/RPC de mensajería/push no creadas por migraciones (drift).

Otros puntos marcados:
  - Crear/editar rutina y finalizar workout SIN transacción (riesgo duplicados).
  - target_reps es TEXT (rango) pero el código lo trata como number.
  - /api/spotify/debug sin auth (exponer prefijo client id) → ✅ eliminado.
  - /api/youtube/search huérfano.
  - Buckets/iconos faltantes, SW cachea respuestas autenticadas de Supabase.
  - NFC en iOS no es viable desde PWA (requiere plugin nativo + entitlements).
  - next build / npm / node -e crashean en el entorno actual
    (Node v26 + glibc, "free(): invalid pointer"). El typecheck sí corre con:
    MALLOC_CHECK_=0 ./node_modules/.bin/tsc --noEmit
